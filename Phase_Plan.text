### SCREEN 10: Checklist Builder (`/checklists/new` and `/checklists/[id]/edit`)

**API:** `POST /api/checklists` or `PUT /api/checklists/[id]`

**This is the most complex frontend component.**

**Header section:**

| Field | Type | Required |
|-------|------|----------|
| Checklist Name | text input | yes |
| Description | textarea | no |
| Mark as Template | checkbox/toggle | no |

**Items section (sortable list):**

Each item row has:

| Field | Type | Required | Conditional Display |
|-------|------|----------|-------------------|
| Field Name | text input | yes | always |
| Field Type | select | yes | always: NUMBER, BOOLEAN, TEXT, SELECT |
| Condition | select | yes | depends on field type (see below) |
| Threshold Value | dynamic input | yes | depends on field type + condition |
| Unit | text input | no | only for NUMBER |
| Options | tag input | yes* | only for SELECT |
| Description | text input | no | always |
| Required | checkbox | no | always |
| Sort Order | auto (drag order) | auto | always |

**Condition options by field type:**

| Field Type | Available Conditions |
|------------|---------------------|
| NUMBER | LESS_THAN, GREATER_THAN, EQUALS, RANGE |
| BOOLEAN | MUST_BE_PRESENT, IS_TRUE |
| TEXT | MUST_CONTAIN, EQUALS |
| SELECT | EQUALS |

**Threshold Value input by type:**

| Field Type + Condition | Input Type | Example |
|------------------------|-----------|---------|
| NUMBER + LESS_THAN | number input | 50 |
| NUMBER + GREATER_THAN | number input | 100 |
| NUMBER + EQUALS | number input | 7.0 |
| NUMBER + RANGE | two number inputs (min, max) | 50 - 100 |
| BOOLEAN + MUST_BE_PRESENT | no input needed (disabled) | — |
| BOOLEAN + IS_TRUE | no input needed (disabled) | — |
| TEXT + MUST_CONTAIN | text input | "certified" |
| TEXT + EQUALS | text input | "ISO 9001" |
| SELECT + EQUALS | dropdown from options | "Pass" |

**Item actions per row:**
- Drag handle (reorder)
- Duplicate
- Delete

**Bottom actions:**
- "Add Item" button
- "Save Checklist" primary button
- "Cancel" secondary button

## GREEN DESIGN SYSTEM

Now for the aesthetic. Here is the complete design specification.

### Design Direction: **"Forest Ink"**

A dark, grounded theme inspired by deep forest tones. Not neon green — think moss, fern, lichen, and moonlight through canopy. Professional enough for auditors, beautiful enough that they enjoy using it.

### Color Palette

```
:root {
  /* Background layers */
  --bg-deep:      #060d09;     /* deepest background */
  --bg-base:      #0b1610;     /* main background */
  --bg-surface:   #111f17;     /* cards, panels */
  --bg-elevated:  #182a1f;     /* modals, dropdowns, hover states */
  
  /* Borders */
  --border:       #1e3328;     /* default borders */
  --border-focus: #2d5a42;     /* focused input borders */
  
  /* Green accent spectrum */
  --green-50:     #f0fdf4;     /* lightest tint */
  --green-100:    #dcfce7;
  --green-200:    #bbf7d0;
  --green-300:    #86efac;     /* light accent */
  --green-400:    #4ade80;     /* primary accent */
  --green-500:    #22c55e;     /* primary */
  --green-600:    #16a34a;     /* hover */
  --green-700:    #15803d;     /* active */
  --green-800:    #166534;     /* deep accent */
  --green-900:    #14532d;     /* badge backgrounds */
  
  /* Text */
  --text-primary: #e8f5ec;     /* main text — warm white with green tint */
  --text-secondary: #94b8a4;   /* secondary text */
  --text-muted:   #5a7d6a;     /* muted text */
  --text-inverse: #060d09;     /* text on green backgrounds */
  
  /* Semantic colors */
  --success:      #22c55e;     /* compliant, passed */
  --error:        #f87171;     /* failed, non-compliant */
  --warning:      #fbbf24;     /* needs review, amber */
  --info:         #60a5fa;     /* processing, info states */
  
  /* Special */
  --glow-green:   rgba(34, 197, 94, 0.15);   /* green glow for focus states */
  --glow-soft:    rgba(34, 197, 94, 0.05);    /* subtle green ambient */
  --shadow:       rgba(0, 0, 0, 0.4);
}
```

### Typography

```
Display/Headings:  "Instrument Serif" — elegant, distinctive serif
Body/UI:           "DM Sans" — clean, modern sans-serif
Mono/Code:         "JetBrains Mono" — for extracted text, data values

Font pairing rationale:
  - Instrument Serif gives the headings a refined, editorial quality
  - DM Sans is highly legible at small sizes for tables and forms
  - JetBrains Mono for any raw data or extracted text display
```
