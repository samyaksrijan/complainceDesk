## 1. Product Overview

### What is Compliance Desk?

Compliance Desk is a SaaS web application that helps organizations manage regulatory compliance. Companies upload audit documents or compliance reports, and the system extracts text, matches documents against compliance checklists, evaluates compliance status, and generates detailed reports with pass/fail results, scores, and summaries.

The system uses LLM-powered scanning to auto-generate checklist structures from compliance regulation documents, with a human-in-the-loop review process to verify and correct extracted fields.

### One-line Summary

> Upload documents. Scan against checklists. Get compliance reports.

### Key Differentiators

- **AI-assisted checklist creation**: Upload a regulation PDF, and the system extracts structured checklist fields automatically
- **Human-in-the-loop review**: AI suggestions are always editable before saving
- **Reusable checklists**: Created checklists are saved and auto-matched to future documents
- **Structured compliance evaluation**: Every checklist item gets a definitive pass/fail/not-found status with source evidence

---

## 2. Problem Statement

Organizations deal with multiple compliance requirements — building safety, fire codes, environmental regulations, data privacy laws, ISO standards. Verifying compliance typically involves:

- Manually reading dense regulation documents
- Manually cross-referencing audit reports against regulations
- Tracking compliance status across multiple documents and standards
- No centralized system for managing checklists, documents, and results

**Compliance Desk automates this workflow**: scan regulations into checklists, upload audit documents, run automated compliance checks, and generate structured reports.

## 3. Target Users

### Roles

| Role | Description | Permissions |
|---|---|---|
| **Admin** | Organization administrator. Manages users, checklists, and all documents. | Full access: create/edit/delete everything, manage users, view all reports |
| **Auditor** | Compliance officer or auditor who uploads documents and runs checks. | Upload documents, create/edit checklists, run compliance checks, view all reports |
| **Viewer** | Stakeholder who needs to see compliance status. | View dashboard, view reports (read-only). Cannot upload or edit. |

### User Journey Summary

```
Admin registers org → Creates/invites users →
Auditor uploads compliance regulation → System scans into checklist →
Auditor reviews and saves checklist →
Auditor uploads audit document → System matches to checklist →
System runs compliance check → Report generated →
Viewer reviews report on dashboard
```

### NextAuth Configuration

```typescript
// lib/auth.ts

import NextAuth from "next-auth"
import CredentialsProvider from "next-auth/providers/credentials"
import bcrypt from "bcryptjs"
import { prisma } from "@/lib/prisma"

export const authOptions = {
  providers: [
    CredentialsProvider({
      name: "credentials",
      credentials: {
        email: { label: "Email", type: "email" },
        password: { label: "Password", type: "password" },
      },
      async authorize(credentials) {
        const user = await prisma.user.findUnique({
          where: { email: credentials.email },
          include: { org: true },
        })

        if (!user) throw new Error("No user found")

        const isValid = await bcrypt.compare(
          credentials.password,
          user.passwordHash
        )
        if (!isValid) throw new Error("Invalid password")

        return {
          id: user.id,
          email: user.email,
          name: user.name,
          role: user.role,
          orgId: user.orgId,
          orgName: user.org.name,
        }
      },
    }),
  ],
  session: { strategy: "jwt" },
  callbacks: {
    async jwt({ token, user }) {
      if (user) {
        token.userId = user.id
        token.role = user.role
        token.orgId = user.orgId
        token.orgName = user.orgName
      }
      return token
    },
    async session({ session, token }) {
      session.user.id = token.userId
      session.user.role = token.role
      session.user.orgId = token.orgId
      session.user.orgName = token.orgName
      return session
    },
  },
  pages: {
    signIn: "/login",
  },
}
```

### RBAC Middleware

```typescript
// lib/rbac.ts

import { getServerSession } from "next-auth"
import { authOptions } from "@/lib/auth"
import { NextResponse } from "next/server"
import { Role } from "@prisma/client"

type Handler = (req: Request, context: { user: SessionUser }) => Promise<NextResponse>

export function withAuth(handler: Handler, allowedRoles?: Role[]) {
  return async (req: Request, context?: any) => {
    const session = await getServerSession(authOptions)

    if (!session?.user) {
      return NextResponse.json({ error: "Unauthorized" }, { status: 401 })
    }

    if (allowedRoles && !allowedRoles.includes(session.user.role as Role)) {
      return NextResponse.json({ error: "Forbidden" }, { status: 403 })
    }

    return handler(req, { user: session.user })
  }
}

// Usage:
// export const POST = withAuth(handler, [Role.ADMIN, Role.AUDITOR])
// export const GET = withAuth(handler) // any authenticated user
```

## 9. Feature Specifications

### 9.1 Authentication

#### Register

**Endpoint**: `POST /api/auth/register`

**Input**:
```json
{
  "email": "admin@company.com",
  "password": "securePass123",
  "name": "John Doe",
  "orgName": "Acme Corp"
}
```

**Behavior**:
1. Validate all fields present and valid (Zod schema)
2. Check email not already taken
3. Create Organization record
4. Hash password with bcrypt (10 rounds)
5. Create User with ADMIN role
6. Return session

**Validation Rules**:
- Email: valid email format
- Password: minimum 8 characters
- Name: minimum 2 characters
- OrgName: minimum 2 characters

#### Login

**Endpoint**: `POST /api/auth/login`

**Input**:
```json
{
  "email": "admin@company.com",
  "password": "securePass123"
}
```

**Behavior**:
1. Find user by email
2. Compare password with bcrypt
3. Return JWT session via NextAuth

**Error Responses**:
- 401: Invalid credentials
- 400: Missing fields

### 9.2 Document Management

#### Upload Document

**Endpoint**: `POST /api/documents/upload`

**Input**: Multipart form data
- `file`: PDF, DOCX, PNG, JPG, or TXT file (max 10MB)
- `name`: Document name (string)

**Behavior**:
1. Validate file type and size
2. Save file to `/uploads/{orgId}/{timestamp}-{originalFilename}`
3. Create Document record with status UPLOADED
4. Trigger text extraction pipeline:
   - PDF → `pdf-parse`
   - DOCX → `mammoth.extractRawText`
   - PNG/JPG → `tesseract.js`
   - TXT → `fs.readFile`
5. Store extracted text in database
6. Update status → UNMATCHED
7. Log activity: `document.uploaded`
8. Return document record

**Error Handling**:
- 400: Invalid file type, file too large
- 500: Extraction failure (still save document, mark as UPLOADED with error note)

#### List Documents

**Endpoint**: `GET /api/documents`

**Query Params**:

```json
      "thresholdValue": "staircase",
      "options": ["staircase", "ramp", "elevator"],
      "sortOrder": 4
    },
    {
      "fieldName": "Load Capacity",
      "fieldType": "NUMBER",
      "unit": "kN/m²",
      "condition": "RANGE",
      "thresholdValue": [2.5, 10],
      "sortOrder": 5
    }
  ]
}
```

**Validation Rules**:
- `name`: required, min 2 chars
- `items`: required, array with at least 1 item
- Each item:
  - `fieldName`: required
  - `fieldType`: required, enum
  - `condition`: required, must be valid for the given `fieldType`
  - `thresholdValue`: required, type must match `fieldType`
- **Condition-Type Compatibility Matrix**:

| fieldType | Allowed conditions |
|---|---|
| NUMBER | LESS_THAN, GREATER_THAN, EQUALS, RANGE |
| BOOLEAN | IS_TRUE, MUST_BE_PRESENT |
| TEXT | EQUALS, MUST_CONTAIN |
| SELECT | EQUALS |

**Behavior**:
1. Validate input (Zod)
2. Validate condition-type compatibility for each item
3. Create Checklist + all ChecklistItems in a transaction
4. Log activity: `checklist.created`
5. Return created checklist with items

### 9.5 Compliance Engine

#### Match Document to Checklist

**Endpoint**: `POST /api/documents/{id}/match`

**Permissions**: ADMIN, AUDITOR

**Input** (optional):
```json
{
  "checklistId": "cl_123"
}
```

**Behavior**:
- If `checklistId` provided: manual match, skip auto-match
- If no body: run auto-match:
  1. Extract keywords from document text
  2. Query org's checklists
  3. Score each checklist by keyword/tag overlap
  4. If top match score > threshold: set as match
  5. If no confident match: return null (status stays UNMATCHED)
- Update `document.matchedChecklistId`
- Update `document.status` → MATCHED
- Log activity: `document.matched`

**Response**:
```json
{
  "matched": true,
  "checklistId": "cl_123",
  "checklistName": "Building Safety Compliance",
  "confidence": 0.92,
  "matchType": "auto"
}
```

Or if no match:
```json
{
  "matched": false,
  "suggestions": [
    { "id": "cl_456", "name": "Fire Safety", "score": 0.45 },
    { "id": "cl_789", "name": "Environmental", "score": 0.30 }
  ]
}
```

#### Run Compliance Check

**Endpoint**: `POST /api/documents/{id}/check`

**Permissions**: ADMIN, AUDITOR

**Precondition**: Document must have a matched checklist

**Behavior**:
1. Fetch document with extracted text
2. Fetch matched checklist with all items
3. Call LLM to extract actual values from document for each checklist field
4. Evaluate each item:

| fieldType | condition | PASS when |
|---|---|---|
| NUMBER | LESS_THAN | extractedValue < thresholdValue |
| NUMBER | GREATER_THAN | extractedValue > thresholdValue |
| NUMBER | EQUALS | extractedValue == thresholdValue |
| NUMBER | RANGE | thresholdValue[0] <= extractedValue <= thresholdValue[1] |
| BOOLEAN | IS_TRUE | extractedValue == true |
| BOOLEAN | MUST_BE_PRESENT | extractedValue == true |
| TEXT | EQUALS | extractedValue.toLowerCase() == thresholdValue.toLowerCase() |
| TEXT | MUST_CONTAIN | extractedValue.toLowerCase() contains thresholdValue.toLowerCase() |
| SELECT | EQUALS | extractedValue in options list |

5. If value not found in document: status = NOT_FOUND
6. If value ambiguous or parse error: status = NEEDS_REVIEW
7. Calculate score: `(passedItems / (totalItems - notFoundItems)) * 100`
8. Generate LLM summary (2-3 sentences)
9. Save ComplianceResult + ComplianceResultItems
10. Update document status: score >= 100 → COMPLIANT, else NON_COMPLIANT
11. Log activity: `document.checked`

**Response**:
```json
{
  "id": "res_789",
  "overallScore": 85.7,
  "totalItems": 7,
  "passedItems": 6,
  "failedItems": 1,
  "notFoundItems": 0,

  "items": [
    {
      "checklistItemId": "item_1",
      "fieldName": "Building Height",
      "status": "PASS",
      "expected": "less_than 50 meters",
      "extractedValue": "42",
      "sourceExcerpt": "Building height: 42 meters (measured from ground level)",

    },
    {

      "fieldName": "Fire Resistance Rating",
      "status": "FAIL",
      "expected": "greater_than 2 hours",
      "extractedValue": "1.5",
```

### LLM Response Handling

```typescript
// services/llm.ts

async function callLLM(systemPrompt: string, userPrompt: string): Promise<string> {
  // Try Groq first
  try {
    const response = await groq.chat.completions.create({
      model: GROQ_CONFIG.model,
      temperature: GROQ_CONFIG.temperature,
      max_tokens: GROQ_CONFIG.maxTokens,
      messages: [
        { role: "system", content: systemPrompt },
        { role: "user", content: userPrompt },
      ],
      response_format: { type: "json_object" }, // Groq supports this
    })
    return response.choices[0].message.content
  } catch (groqError) {
    console.error("Groq failed, trying Gemini:", groqError)

    // Fallback to Gemini
    const model = genAI.getGenerativeModel({ model: GEMINI_CONFIG.model })
    const result = await model.generateContent(
      `${systemPrompt}\n\n${userPrompt}`
    )
    return result.response.text()
  }
}

function parseJSONResponse<T>(raw: string, schema: ZodSchema<T>): T {
  // Try direct parse
  try {
    const parsed = JSON.parse(raw)
    return schema.parse(parsed)
  } catch {
    // Try extracting JSON from markdown code block
    const match = raw.match(/```(?:json)?\s*([\s\S]*?)```/)
    if (match) {
      return schema.parse(JSON.parse(match[1]))
    }
    throw new Error("Failed to parse LLM response as JSON")
  }
}
```

### Retry Logic

```
- On LLM API error → retry once with same provider
- On 2nd failure → switch to fallback provider
- On JSON parse error → retry once with same provider 
  (add "Return ONLY valid JSON" to prompt)
- On 2nd parse failure → throw LLM_PARSE_ERROR
```

```
1. Register new org → lands on dashboard (empty state)

5. Review extracted items → edit low-confidence ones → save
6. Navigate to Documents → upload audit PDF
7. View document → extracted text shown
8. Click "Match to Checklist" → auto-suggests or manual select
9. Click "Run Compliance Check" → processing indicator
10. View report → score gauge, per-item results, summary
11. Export PDF → downloads
12. Return to Dashboard → stats updated, activity logged
```
